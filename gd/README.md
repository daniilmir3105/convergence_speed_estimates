# Gradient Descent: оптимизированный finite-horizon эксперимент

Здесь находится основной finite-horizon эксперимент для обычного градиентного
спуска без momentum. Он использует ту же общую логику, что и эксперимент
Heavy Ball из папки `hb`.

Диапазон числа обусловленности:

\[
1.1\leq\kappa=\frac{L}{l}\leq 20000.
\]

Итоговый сохранённый объект принимает только два внешних признака — `L` и `l`
— и возвращает шаг `alpha`.

## Какой таргет используется

Для каждого сочетания числа обусловленности и проверяемого шага выполняется
ровно тот эксперимент, который задан в условии:

\[
J_{300}=\frac{1}{16\cdot300}
\sum_{i=1}^{16}
\log_{10}\left[
\max\left(
\frac{f(x_{300}^{(i)})}{f(x_0^{(i)})},10^{-300}
\right)
\right].
\]

Здесь используется двумерная положительно определённая квадратичная функция

\[
f(x)=\frac12\left(Lx_1^2+l x_2^2\right).
\]

После нормировки `l=1`, `L=kappa` результат не зависит от общего масштаба `L`
и `l`, а зависит от `kappa` и безразмерного шага `alpha*L`.

Чем меньше, то есть чем отрицательнее, `J_300`, тем сильнее в среднем
уменьшилась функция за одну итерацию на горизонте 300 шагов.

Первая ML-модель обучается не на самом `J_300`, а на указанной в постановке
масштабированной величине:

\[
\boxed{y_{\mathrm{first}}=\sqrt{\kappa}\,J_{300}}.
\]

Умножение на `sqrt(kappa)` используется только как техническое
масштабирование для регрессии. При фиксированном `kappa` оно не меняет шаг,
который минимизирует прогноз.

## Параметр поиска

Внутри кода используется

\[
q=\frac{\alpha L}{2},\qquad \alpha=\frac{2q}{L}.
\]

Для устойчивого GD на рассматриваемой квадратичной задаче требуется `0<q<1`.
В коде верхняя граница равна `0.99999`. Это достаточно, чтобы при
`kappa=20000` область поиска содержала классический теоретический оптимум.

## Теоретическое значение для сравнения

Аналогом формул Поляка для постоянного шага обычного Gradient Descent служит
классический оптимальный шаг на положительно определённой квадратичной функции:

\[
\boxed{\alpha_{\mathrm{theory}}=\frac{2}{L+l}}.
\]

В безразмерной форме:

\[
q_{\mathrm{theory}}
=\frac{\alpha_{\mathrm{theory}}L}{2}
=\frac{\kappa}{\kappa+1}.
\]

Важно: эта формула не используется как обучающая метка. Она вычисляется после
поиска и нужна только для сопоставления. Поэтому новый эксперимент проверяет,
какой шаг предпочитает именно конечный критерий `J_300`, а не учится
воспроизводить заранее заданную формулу.

## Пайплайн

1. Генерируются 16 фиксированных начальных точек. Одни и те же точки
   используются для всех кандидатов, поэтому сравнение шагов честное.
2. Независимый точный oracle минимизирует реальный `J_300` по плотной сетке и
   локальным уточнениям. Он не использует ML-модели и теоретическую alpha.
3. Создаётся forward-датасет из разных `kappa` и кандидатных шагов. Шаги
   выбираются по широкой и сгущённой у границы устойчивости сеткам без
   использования теоретической `alpha` как центра выборки.
4. `HistGradientBoostingRegressor` учится предсказывать
   `sqrt(kappa) * J_300`.
5. Forward-модель ранжирует кандидатные шаги для большого набора пар `(L,l)`.
6. Лучшие кандидаты повторно оцениваются по точному `J_300` и локально
   уточняются. Полученные значения становятся finite-horizon метками.
7. Финальный `GradientBoostingRegressor` учится восстанавливать устойчивый
   безразмерный параметр `q` по признакам, вычисленным только из `L` и `l`.
8. Публичная сохранённая модель преобразует прогноз обратно в
   `alpha=2q/L`, поэтому её интерфейс имеет требуемый вид `(L,l) -> alpha`.
9. Результат сравнивается и с finite-horizon метками, и с формулой
   `2/(L+l)`, а также по фактическому значению `J_300`.

Точное вычисление `J_300` оптимизировано: для GD координаты после 300 шагов
имеют замкнутую формулу. Поэтому код не выполняет отдельный Python-цикл из 300
итераций для каждой строки, но результат математически совпадает с явным
запуском 300 итераций.

## Полный запуск

Команду нужно выполнять из корня проекта. Важно использовать `-m`, потому что
итоговая joblib-модель содержит класс из этого Python-пакета.

```powershell
.\venv\Scripts\python.exe -m gd.pipeline
```

## Быстрый пробный запуск

Этот вариант нужен только для проверки окружения и формата выходных файлов.
Его метрики нельзя считать итоговыми из-за малого объёма данных.

```powershell
.\venv\Scripts\python.exe -m gd.pipeline `
  --forward-groups 200 `
  --forward-candidates 48 `
  --forward-iterations 100 `
  --oracle-points 64 `
  --oracle-grid 96 `
  --oracle-refine 25 `
  --oracle-stages 2 `
  --meta-pairs 800 `
  --meta-estimators 150 `
  --search-grid 96 `
  --predicted-refine 32 `
  --exact-top-k 16 `
  --exact-refine 21 `
  --exact-stages 2 `
  --batch-size 64
```

## Использование готовой модели

Например, для `L=1000` и `l=1`:

```powershell
.\venv\Scripts\python.exe -m gd.predict 1000 1
```

Скрипт напечатает:

- прогноз finite-horizon ML-модели;
- теоретическое значение `2/(L+l)`;
- абсолютное и относительное различие.

Программный вызов:

```python
from gd.predict import predict

alpha = predict(L=1000.0, l=1.0)
```

## Что будет сохранено

После полного запуска появятся:

- `models/hist_gradient_boosting_finite_rate.joblib` — первая модель,
  предсказывающая `sqrt(kappa) * J_300`;
- `models/gradient_boosting_alpha.joblib` — итоговая публичная модель
  `(L,l) -> alpha`;
- `data/forward_dataset.pkl` — обучающие данные первой модели;
- `data/oracle_diagnostic.csv` — независимый точный контрольный поиск;
- `data/inverse_labels_all.csv` — finite-horizon метки для второй модели;
- `data/direct_model_test.csv` — независимая тестовая часть с прогнозами;
- `results/metrics.json` — конфигурация и все метрики;
- `results/oracle_vs_theory.png` — oracle против классической теории;
- `results/alpha_model_vs_finite_labels.png` — итоговая модель против меток.

В `metrics.json` теперь остаются только четыре итоговых `R²`:

```text
metrics.forward_model.validation_scaled_r2
metrics.forward_model.near_optimum_scaled_r2
metrics.forward_model.validation_raw_J300_r2
metrics.final_model_vs_classical_gd_theory.alpha_r2
```

- `validation_scaled_r2` — качество первой модели на отдельной валидационной
  выборке для обучающего таргета `sqrt(kappa) * J_300`;
- `near_optimum_scaled_r2` — то же качество только на 20% лучших по истинному
  `J_300` кандидатов внутри каждого валидационного `kappa`;
- `validation_raw_J300_r2` — качество после возврата прогноза в исходные
  единицы `J_300`;
- `alpha_r2` — сходство шага итоговой модели с классической формулой GD
  `alpha = 2/(L+l)`.

Oracle и точное уточнение остаются частью поиска и сохраняются в
диагностических данных, но их дополнительные метрики больше не записываются в
`metrics.json`.

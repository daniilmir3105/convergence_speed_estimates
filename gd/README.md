# Gradient Descent alternative

Альтернативный конвейер для обратной задачи градиентного спуска. Внутренняя
`sklearn.ensemble.GradientBoostingRegressor` обучается предсказывать асимптотическую скорость сходимости, после
чего по ней находится оптимальный шаг и обучается финальная модель
`(L, l) -> alpha`.

## Таргет первой модели

Первая, или forward-модель, должна присвоить каждому кандидатному шагу
`alpha` одно число: оценку того, насколько быстро с ним будет сходиться
градиентный спуск. Для этого используется ML-таргет

\[
\boxed{
y_{\mathrm{GD}}=
2\kappa\log_{10}\!\left(\max(\rho_{\mathrm{GD}},10^{-15})\right)
},
\qquad
\kappa=\frac{L}{l}.
\]

Чем меньше, то есть чем отрицательнее, таргет, тем лучше кандидатный шаг.

### Что такое `rho` для Gradient Descent

Для положительно определённой квадратичной функции рассматриваются два крайних
собственных значения гессиана:

- `L` — максимальная кривизна, то есть самое крутое направление;
- `l` — минимальная кривизна, то есть самое пологое направление.

В направлении с собственным значением `lambda` одна итерация Gradient Descent
имеет вид

\[
x_{k+1}=(1-\alpha\lambda)x_k.
\]

Коэффициент `1 - alpha * lambda` показывает, какая доля координаты останется
после следующего шага. Для двух крайних направлений коэффициенты равны

\[
r_L=1-\alpha L,
\qquad
r_l=1-\alpha l.
\]

Общую скорость ограничивает самое медленное направление, поэтому берётся
наибольший модуль:

\[
\boxed{
\rho_{\mathrm{GD}}=
\max\left(|1-\alpha L|,|1-\alpha l|\right)
}.
\]

Интерпретация:

- `rho < 1` — координаты затухают и GD сходится;
- `rho` близко к `1` — сходимость медленная;
- `rho = 1` — затухания нет;
- `rho > 1` — GD расходится;
- чем ближе `rho` к нулю, тем быстрее сходимость.

Знак коэффициента отвечает за направление движения. Например, отрицательное
значение означает перескакивание через минимум, но скорость затухания задаётся
его модулем.

### Нормированный шаг

Forward-модель использует безразмерный шаг

\[
u=\alpha L.
\]

Поскольку `kappa = L/l`, имеем

\[
\alpha l=\frac{u}{\kappa}.
\]

Поэтому формула спектрального радиуса записывается без абсолютного масштаба
задачи:

\[
\boxed{
\rho_{\mathrm{GD}}=
\max\left(
|1-u|,
\left|1-\frac{u}{\kappa}\right|
\right)
}.
\]

После обратного поиска обычный шаг восстанавливается как

\[
\alpha=\frac{u}{L}.
\]

### Зачем нужны логарифм и множитель 2

Если координаты асимптотически изменяются как

\[
x_k\sim\rho^k,
\]

то значение квадратичной функции, зависящее от квадрата координат, изменяется
примерно как

\[
f(x_k)\sim\rho^{2k}.
\]

Поэтому логарифмическая скорость значения функции на одну итерацию равна

\[
\frac1k\log_{10}(\rho^{2k})=2\log_{10}\rho.
\]

Логарифм превращает последовательное умножение в удобную шкалу:

| `rho` | `2 * log10(rho)` | Интерпретация |
|---:|---:|---|
| `0.99` | `-0.0087` | медленная сходимость |
| `0.90` | `-0.0915` | сходимость |
| `0.50` | `-0.6021` | быстрая сходимость |
| `1.00` | `0` | затухания нет |
| `1.10` | `0.0828` | расходимость |

`max(rho, 1e-15)` является только защитой от вычисления `log10(0)`.

### Почему используется множитель `kappa`

Физически интерпретируемая скорость равна

\[
J_{\mathrm{GD}}=2\log_{10}\rho_{\mathrm{GD}}.
\]

При увеличении числа обусловленности оптимальная скорость GD ухудшается
приблизительно пропорционально `1/kappa`. Значения `J_GD` становятся очень
близкими к нулю, и регрессионной модели трудно различать соседние шаги.
Поэтому для обучения используется масштабированный таргет

\[
y_{\mathrm{GD}}=\kappa J_{\mathrm{GD}}.
\]

Во время поиска `kappa` фиксировано, поэтому все кандидатные шаги одной задачи
умножаются на одну положительную константу. Это растягивает шкалу, но не меняет
победителя:

\[
\arg\min_u J_{\mathrm{GD}}
=
\arg\min_u \kappa J_{\mathrm{GD}}.
\]

Таким образом, `2*log10(rho)` описывает скорость сходимости, а умножение на
`kappa` является технической нормализацией для Gradient Boosting.

### Вычисление одной строки датасета

Упрощённая программная логика выглядит так:

```python
kappa = L / l
u = alpha * L

rate_L = abs(1 - u)
rate_l = abs(1 - u / kappa)
rho = max(rate_L, rate_l)

target_rate = 2 * log10(max(rho, 1e-15))
ml_target = kappa * target_rate
```

Forward-модель получает четыре признака:

```text
kappa
log(kappa)
u = alpha * L
u / 2
```

Последний признак показывает долю шага от границы устойчивости `u=2`. Модель
учится предсказывать `ml_target`, после чего обратный поиск выбирает значение
`u` с самым маленьким прогнозом.

### Сравнение с Heavy Ball

Принцип у GD и Heavy Ball одинаков:

\[
\text{скорость функции}=2\log_{10}\rho.
\]

Различается вычисление `rho` и техническое масштабирование:

| Алгоритм | Спектральный радиус | ML-таргет |
|---|---|---|
| Gradient Descent | `max(abs(1-u), abs(1-u/kappa))` | `2*kappa*log10(rho)` |
| Heavy Ball | Максимальный модуль четырёх характеристических корней | `2*sqrt(kappa)*log10(rho)` |

У GD нет momentum и зависимости от предыдущей точки, поэтому квадратное
характеристическое уравнение не требуется. У Heavy Ball присутствует `beta`,
а новое состояние зависит от двух предыдущих состояний, поэтому вычисляются
два корня для направления `L` и два для направления `l`.

### Отличие от finite-horizon оценки

Текущий GD-пайплайн не выполняет 300 реальных итераций для вычисления каждой
обучающей метки. Он сразу вычисляет асимптотическую скорость через `rho`.

Finite-horizon подход запускает алгоритм на фиксированное число итераций и
измеряет фактическое отношение `f(x_K)/f(x_0)`. Спектральный таргет анализирует
долгосрочную скорость цикла без его многократного исполнения. При большом `K`
finite-horizon оценка приближается к `2*log10(rho)`, но при конечном горизонте
дополнительно зависит от начальной точки и переходного процесса.

## Полный запуск

Из корня проекта:

```powershell
.\venv\Scripts\python.exe gd\pipeline.py
```

Рекомендуемый лаунчер с полным набором параметров нового диапазона:

```powershell
.\train_gd.cmd
```

Для быстрой проверки используйте `.\train_gd.cmd -Quick`.

Конвейер создаст датасеты и сохранит:

- `models/gradient_boosting_terminal_rate.joblib` — внутреннюю forward-модель;
- `models/gradient_boosting_alpha.joblib` — финальную модель `(L,l) -> alpha`;
- `results/metrics.json` — метрики;
- `results/meta_vs_theory.png` — график против теории;
- `data/inverse_train.csv` и `data/meta_test.csv` — результаты эксперимента.

## Использование готовой модели

```powershell
.\venv\Scripts\python.exe gd\predict.py 40 10
```

Скрипт выводит ML-прогноз, теоретический шаг `2/(L+l)` и абсолютную ошибку.

Программный вызов:

```python
from gd.predict import predict, gd_theory

alpha = predict(L=40, l=10)
alpha_theory = gd_theory(L=40, l=10)
```

Модель обучена для `l` от 1 до 50 и `L/l` от 1.1 до 20000. Значения `L/l`
выбираются равномерно по логарифмической шкале. Экстраполяция за
пределы этого диапазона не проверялась.

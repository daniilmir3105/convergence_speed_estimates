# Оценка скорости гиподифференциального спуска с учетом всех компонент

Это отдельный самодостаточный эксперимент, не изменяющий содержимое папок `hypodifferential_rate` и `hypodifferential_rate_enhanced` и не импортирующий из них численный алгоритм. Его цель — проверить замечание о том, что глобальные границы `L` и `l` и число функций под максимумом не позволяют модели различить задачи с разным внутренним составом. Поэтому здесь модели получают не только число компонент, но и спектральные границы каждой квадратичной функции.

## Постановка

Исследуется гиподифференциальный спуск для функции

\[
f(x)=\max_{1\le j\le m}\frac12x^{\mathsf T}A_jx,
\]

где все матрицы `A_j` симметричны и положительно определены. Минимум известен заранее: `x*=0`, `f*=0`. Направление спуска получается как отрицательная проекция нуля на гиподифференциал, а шаг на каждой итерации находится точным одномерным поиском. Постоянный шаг не является параметром модели и не предсказывается.

Таргет оставлен без изменений:

\[
J_{300}=\frac{1}{16\cdot300}\sum_{i=1}^{16}
\log_{10}\!\left[\max\!\left(
\frac{f(x_{300}^{(i)})}{f(x_0^{(i)})},10^{-300}
\right)\right].
\]

Дополнительно выводится `rho = 10^J_300`: средний коэффициент уменьшения ошибки за одну итерацию. Чем меньше `rho` и чем отрицательнее `J_300`, тем быстрее сходимость.

## Как учтено замечание научного руководителя

В стандартной конфигурации число функций под максимумом равномерно меняется от 2 до 20, а размерность — от 2 до 6. Для каждой компоненты вычисляются собственные минимальная и максимальная границы `l_i` и `L_i`. Компоненты упорядочиваются по убыванию `L_i`, после чего их границы записываются в вектор фиксированной длины. Отсутствующие позиции заполняются нулями и сопровождаются отдельным индикатором присутствия.

Модели фактически получают все пары `L_i,l_i`, но в логарифмическом безразмерном виде относительно общего `l`. Это преобразование не теряет относительную спектральную информацию и убирает общий масштаб функции, который при точном линейном поиске не меняет траекторию. В признаки также входят размерность, число компонент и глобальное число обусловленности.

Чтобы проверить, действительно ли сведения об отдельных функциях полезны, для каждого алгоритма строятся две версии:

- основная — со всеми индивидуальными `L_i,l_i`;
- контрольная — только с размерностью, числом компонент и глобальными `L/l`.

Обе версии независимо настраиваются по валидационной выборке. Итоговые показатели рассчитываются только на тестовой выборке, которая не участвует ни в подборе параметров, ни в обучении. Разбиение составляет 60%/20%/20%.

## Датасет и время вычислений

По умолчанию генерируется 5000 функций с равномерным покрытием сочетаний размерности и числа компонент и логарифмическим покрытием диапазона числа обусловленности от 1.1 до 20000. Для каждой функции выполняются 16 запусков по правилу исходного эксперимента.

Диапазон до 20 компонент выбран как первая расширенная постановка: точный линейный поиск проверяет попарные пересечения квадратичных компонент, поэтому его стоимость растет с их количеством. После генерации сохраняется отдельная таблица времени вычислений по каждому значению `n_pieces`. По ней можно определить, с какого числа компонент рост времени становится существенным, а затем повторить генерацию, например, до 30 компонент.

## Модели

На одном и том же разбиении сравниваются:

- `GradientBoostingRegressor`;
- `ExtraTreesRegressor`;
- `EIKGPolynomialRegressor` — элементарный образ полинома Колмогорова—Габора.

Для первых двух алгоритмов конфигурация выбирается по минимальному MSE на валидации. Для ЭОПКГ таким же образом выбирается степень полинома. После выбора модель переобучается на объединении обучающей и валидационной частей и один раз оценивается на тесте.

Основной итог находится в `results/summary_metrics.json`. Для каждой модели там приведены тестовые `R²`, MAE, MSE и RMSE для `J_300` и `rho`, отдельно для полного и контрольного набора признаков. График `results/test_r2_feature_comparison.png` показывает, повысилось ли тестовое `R²` после добавления всех индивидуальных границ.

## Запуск

Из корня проекта установите зависимости:

```powershell
.\venv\Scripts\python.exe -m pip install -r hypodifferential_rate_0_1\requirements.txt
```

Сгенерируйте датасет:

```powershell
.\venv\Scripts\python.exe -m hypodifferential_rate_0_1.generate_dataset --n-jobs -1
```

Обучите и сравните три семейства моделей:

```powershell
.\venv\Scripts\python.exe -m hypodifferential_rate_0_1.train --n-jobs -1
```

Для отдельного эксперимента с более широким диапазоном числа функций:

```powershell
.\venv\Scripts\python.exe -m hypodifferential_rate_0_1.generate_dataset --instances 7500 --pieces-max 30 --n-jobs -1
.\venv\Scripts\python.exe -m hypodifferential_rate_0_1.train --n-jobs -1
```

При изменении `pieces-max` датасет и модели необходимо построить заново, поскольку меняется ширина входного вектора.

## Прогноз для своей функции

Сохраните массив матриц формы `(n_pieces, dimension, dimension)` в NPY-файл и выполните:

```powershell
.\venv\Scripts\python.exe -m hypodifferential_rate_0_1.predict --instance path\to\matrices.npy
```

По умолчанию используется Extra Trees. Другую сохраненную модель можно передать через `--model`, например `hypodifferential_rate_0_1\models\eikg_J300.joblib`.

Код при подготовке папки не запускался; команды выше предназначены для самостоятельного запуска эксперимента.

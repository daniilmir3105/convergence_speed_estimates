РЕШЕНИЕ ОБРАТНОЙ ЗАДАЧИ ДЛЯ МЕТОДА HEAVY BALL
================================================

1. Постановка задачи
--------------------

Рассматривается квадратичная функция двух переменных

    f(x) = 0.5 * (L * x_1^2 + l * x_2^2),

где L — максимальное собственное значение матрицы Гессе, а l — минимальное
собственное значение. Предполагается, что L >= l > 0.

Метод Heavy Ball имеет вид

    x_{k+1} = x_k - alpha * grad f(x_k) + beta * (x_k - x_{k-1}).

Прямая задача состоит в том, чтобы по известным L, l, alpha и beta построить
траекторию алгоритма и определить скорость уменьшения функции.

В обратной задаче известны только L и l. Требуется найти такие alpha и beta,
при которых алгоритм сходится наиболее быстро, а затем обучить две модели:

    model_alpha(L, l) -> alpha,
    model_beta(L, l)  -> beta.

Для проверки используются теоретические параметры Поляка:

    alpha_theory = 4 / (sqrt(L) + sqrt(l))^2,

    beta_theory = ((sqrt(L) - sqrt(l)) /
                   (sqrt(L) + sqrt(l)))^2.


2. Почему исходная композиция моделей не решила обратную задачу
----------------------------------------------------------------

Первая модель градиентного бустинга обучалась продолжать уже известную траекторию Heavy
Ball. Среди её признаков находились последние значения функции, изменение
логарифма функции, амплитуда колебаний и другие признаки истории. Поэтому она
очень хорошо отвечала на вопрос:

    «Какое значение функции будет следующим у данной траектории?»

Но обратная задача задаёт другой вопрос:

    «Какая из большого количества пар (alpha, beta) является лучшей?»

Небольшая ошибка регрессии почти не портила график отдельной траектории и R^2,
но могла поменять местами двух близких кандидатов при вычислении argmin.

Кроме того, старый генератор:

  * завершал быстрые траектории досрочно;
  * ограничивал логарифмическую цель уровнем примерно -30;
  * почти не содержал очень быстрых траекторий на 300-й итерации.

В действительности теоретически оптимальная траектория могла иметь
log10(f_300 / f_0) порядка -100 или -200, но старая модель таких значений
никогда не видела. В результате она неправильно ранжировала кандидатов, а
последующие метамодели успешно воспроизводили уже ошибочно найденные параметры.


3. Основная идея альтернативного решения
-----------------------------------------

Для обратной задачи была обучена отдельная прямая модель. Она не продолжает
историю траектории, а сразу оценивает терминальную скорость сходимости заданной
пары (alpha, beta).

Для каждого кандидата выполняются ровно K = 300 шагов Heavy Ball. Досрочная
остановка не используется. Целевая величина определяется формулой

    J = mean_x0(log10(max(f_K / f_0, 1e-300))) / K.

Здесь усреднение выполняется по нескольким фиксированным начальным точкам x0.
Деление на K не меняет положение минимума, но приводит значения цели к более
удобному численному масштабу.

Использование порога 1e-300 вместо 1e-30 позволяет различать быстрые
траектории даже на 300-й итерации. Все вычисления точных траекторий выполняются
в float64.


4. Безразмерные параметры
-------------------------

Для ускорения обучения и улучшения обобщения используется число
обусловленности

    kappa = L / l

и безразмерный шаг

    alpha_L = alpha * L.

Если спектр нормировать до пары (kappa, 1), динамика квадратичной задачи
определяется только величинами

    kappa, alpha_L, beta.

Абсолютный масштаб L и l для внутренней forward-модели не нужен. После решения
обратной задачи настоящий шаг восстанавливается как

    alpha = alpha_L / L.

Дополнительно используется нормализованная доля от границы устойчивости:

    stability_ratio = alpha_L / (2 * (1 + beta)).

Внутренняя модель GradientBoostingRegressor получает пять признаков:

    kappa,
    log(kappa),
    alpha_L,
    beta,
    stability_ratio.

Её целевая переменная — терминальная скорость J.


5. Формирование обучающей выборки forward-модели
------------------------------------------------

Обучающая выборка содержит три типа кандидатов.

1. Global-кандидаты

   Случайные beta и alpha_L по всей устойчивой области. Они позволяют модели
   видеть общий рельеф целевой функции, включая плохие параметры.

2. Local-кандидаты

   Кандидаты в окрестности ожидаемого оптимума. Они нужны потому, что для
   обратной задачи особенно важна точность именно около минимума, а не только
   средняя точность на всей области.

3. Anchor-кандидаты

   Теоретическая точка Поляка и несколько небольших отклонений вокруг неё.
   Теория здесь используется только для выбора области более плотного
   сэмплирования. Целевые значения для anchor-кандидатов всё равно вычисляются
   настоящей симуляцией Heavy Ball, а не берутся из теоретической формулы.

Local- и anchor-примеры получают повышенные веса при обучении. Благодаря этому
Градиентный бустинг точнее воспроизводит форму целевой функции около её минимума.

Разбиение forward-датасета на train и validation выполняется по целым значениям
kappa. Кандидаты с одним и тем же kappa не попадают одновременно в обучение и
валидацию. Это проверяет способность модели работать на новых квадратичных
задачах, а не запоминать отдельные группы кандидатов.


6. Совместное решение обратной задачи
-------------------------------------

После обучения forward-модели для каждого нового kappa выполняется совместный
поиск alpha_L и beta.

На первом этапе строится грубая двумерная сетка:

    32 значения alpha_L x 32 значения beta.

Для всех кандидатов одним пакетным вызовом вычисляется прогноз J. Выбирается
пара с минимальным значением.

На втором этапе вокруг найденной точки строится уточняющая сетка:

    16 значений alpha_L x 16 значений beta.

Из неё снова выбирается кандидат с минимальным прогнозом J. Таким образом,
вместо очень плотной сетки по всей области применяется быстрый coarse-to-fine
поиск.

Результатом для каждой пары L, l являются

    alpha_found = alpha_L_found / L,
    beta_found.

Это и есть обучающие метки для двух финальных моделей.


7. Финальные модели
-------------------

Генерируются пары L, l в диапазонах

    l в [1, 50],
    kappa = L/l в [1.1, 20].

Для обучающей части выборки параметры alpha_found и beta_found вычисляются
через описанную выше обратную задачу. После этого обучаются две независимые
Модели GradientBoostingRegressor:

    gradient_boosting_alpha.joblib: признаки [L, l], цель alpha_found;
    gradient_boosting_beta.joblib:  признаки [L, l], цель beta_found.

Таким образом, во время практического использования никакие траектории,
сетки или дополнительные признаки уже не нужны. Пользователь передаёт только
L и l и сразу получает два параметра Heavy Ball.


8. Оптимизации времени выполнения
---------------------------------

В реализации применены следующие оптимизации:

  * нормирование задачи до спектра (kappa, 1);
  * векторное моделирование большого количества траекторий NumPy-массивами;
  * обработка точных траекторий крупными блоками;
  * пакетные предсказания GradientBoostingRegressor;
  * совместная обработка сотен пар L, l;
  * двухступенчатый coarse-to-fine поиск;
  * вычисление обратных меток только для обучающей части выборки;
  * отсутствие интерактивных графиков во время расчётов.

Полный конвейер в текущем окружении выполняется примерно за 30 секунд.

10. Запуск полного конвейера
----------------------------

Из корня проекта выполнить:

    .\venv\Scripts\python.exe hb_alternative\pipeline.py

Команда заново создаст датасет, обучит внутреннюю forward-модель, решит
обратную задачу, обучит две финальные модели и сохранит результаты.


11. Использование готовых моделей
---------------------------------

Пример для L = 40 и l = 10:

    .\venv\Scripts\python.exe hb_alternative\predict.py 40 10

Пример вывода:

    alpha = 0.0448409952
    beta  = 0.1255700812

Программное использование:

    from hb_alternative.predict import predict

    alpha, beta = predict(L=40, l=10)

Финальные модели расположены в файлах

    models/gradient_boosting_alpha.joblib,
    models/gradient_boosting_beta.joblib.


12. Ограничения
---------------

Модели проверялись в диапазонах l от 1 до 50 и kappa от 1.1 до 20. За этими
границами GradientBoostingRegressor будет экстраполировать, поэтому качество не гарантируется.

Найденные параметры оптимизированы для терминального горизонта K = 300 и
квадратичных функций с положительно определённым Гессианом. Для существенно
другого горизонта, другого диапазона обусловленности или неквадратичных задач
желательно заново сформировать датасет и переобучить модели.

Теоретические параметры используются для плотного сэмплирования области около
оптимума и для независимой оценки качества. Поэтому данный эксперимент
демонстрирует, что ML-композиция способна воспроизвести обратное отображение,
но не является полностью независимым машинным выводом формулы Поляка с нуля.

# Heavy Ball: finite-horizon подбор `alpha` и `beta`

Это основной эксперимент проекта для метода тяжёлого шарика. Он строит две
итоговые ML-модели, которые по кривизнам задачи `L` и `l` определяют параметры
оптимизатора `alpha` и `beta` для фиксированного бюджета из 300 итераций.

Диапазон обучения:

\[
1.1\leq\kappa=\frac{L}{l}\leq20000,
\qquad 1\leq l\leq50.
\]

## Критерий качества параметров

Для каждого числа обусловленности и каждой проверяемой пары `(alpha, beta)`
вычисляется:

\[
\boxed{
J_{300}=
\frac{1}{16\cdot300}
\sum_{i=1}^{16}
\log_{10}\left[
\max\left(
\frac{f(x_{300}^{(i)})}{f(x_0^{(i)})},
10^{-300}
\right)
\right]
}.
\]

Здесь:

- `16` — число фиксированных начальных точек;
- `300` — число итераций Heavy Ball;
- `f(x_0)` — значение функции до запуска;
- `f(x_300)` — значение функции после 300 итераций;
- `10^-300` — защита от вычисления `log10(0)`.

Чем меньше `J_300`, тем сильнее в среднем уменьшилась целевая функция за одну
итерацию на заданном горизонте.

Рассматривается двумерная положительно определённая квадратичная функция:

\[
f(x)=\frac12\left(Lx_1^2+l x_2^2\right).
\]

После нормировки `l=1`, `L=kappa` траектория определяется числом
обусловленности и безразмерными параметрами оптимизатора.

## Таргет первой модели

Forward-модель обучается предсказывать масштабированный показатель:

\[
\boxed{
y_{\mathrm{first}}=\sqrt{\kappa}\,J_{300}
}.
\]

Умножение на `sqrt(kappa)` делает различия при больших `kappa` заметнее для
регрессора. Для одной задачи множитель одинаков для всех кандидатных
параметров, поэтому он не меняет положение минимума.

Признаки первой модели:

```text
kappa
log(kappa)
sqrt(kappa)
1 / sqrt(kappa)
alpha_L = alpha * L
beta
q = alpha*L / (2*(1+beta))
```

Первая модель реализована через
`sklearn.ensemble.HistGradientBoostingRegressor`.

## Безразмерный параметр `q`

Во время поиска используется:

\[
q=\frac{\alpha L}{2(1+\beta)}.
\]

После предсказания обычный шаг восстанавливается как:

\[
\alpha=\frac{2q(1+\beta)}{L}.
\]

В коде действуют ограничения:

```text
0 < q <= 0.99999
0 <= beta <= 0.99
```

Они удерживают найденные параметры внутри устойчивой области. Финальные
регрессии предсказывают `q` и `beta`, однако пользовательский интерфейс
возвращает привычные `alpha` и `beta`.

## Пайплайн

1. Генерируются 16 фиксированных начальных точек.
2. Для набора значений `kappa` выполняется exact oracle: прямой поиск минимума
   настоящего `J_300` без ML-моделей.
3. Создаётся forward-датасет из разных `kappa`, `alpha` и `beta`.
4. Первая модель обучается прогнозировать `sqrt(kappa) * J_300`.
5. Forward-модель ранжирует глобальную сетку кандидатных параметров.
6. Лучшие кандидаты повторно оцениваются по точному `J_300`.
7. Выполняются точные локальные уточнения найденного минимума.
8. Полученные `q` и `beta` используются как finite-horizon метки.
9. Два `GradientBoostingRegressor` обучаются отображениям
   `(L,l) -> q` и `(L,l) -> beta`.
10. На выходе `q` преобразуется в `alpha`.

Точное вычисление `J_300` оптимизировано. Для каждой собственной координаты
распространяется один скалярный множитель вместо хранения всех 16 полных
траекторий. Результат алгебраически совпадает с явным выполнением Heavy Ball,
но требует меньше памяти и времени.

## Теоретический ориентир Поляка

После обучения результаты сопоставляются с классическими параметрами:

\[
\alpha_{\mathrm P}=
\frac{4}{(\sqrt L+\sqrt l)^2},
\qquad
\beta_{\mathrm P}=
\left(
\frac{\sqrt L-\sqrt l}{\sqrt L+\sqrt l}
\right)^2.
\]

Точка Поляка не добавляется в кандидаты обратного поиска. Метки `q_found` и
`beta_found` формируются только из глобальной сетки, кандидатов forward-модели
и точного локального уточнения по настоящему `J_300`. Теоретические параметры
вычисляются отдельно после поиска и используются для итогового сравнения.

Генератор forward-датасета сохраняет исходное более плотное сэмплирование
около теоретической области. Это влияет только на расположение обучающих
кандидатов первой модели: таргет каждого кандидата рассчитывается точной
симуляцией, а готовые параметры Поляка не используются как метки. Для полностью
теоретически нейтрального эксперимента потребуется отдельно изменить и схему
сэмплирования forward-датасета.

## Метрики

В `results/metrics.json` сохраняются только пять ключевых `R²`:

```text
metrics.forward_model.validation_scaled_r2
metrics.forward_model.near_optimum_scaled_r2
metrics.forward_model.validation_raw_J300_r2
metrics.final_models_vs_polyak.alpha_r2
metrics.final_models_vs_polyak.beta_r2
```

- `validation_scaled_r2` — качество первой модели на отдельной
  валидационной выборке для `sqrt(kappa) * J_300`;
- `near_optimum_scaled_r2` — качество на 20% лучших по настоящему `J_300`
  кандидатов внутри каждого валидационного `kappa`;
- `validation_raw_J300_r2` — качество после возврата прогноза в исходные
  единицы `J_300`;
- `alpha_r2` и `beta_r2` — сходство выходов итоговых моделей с параметрами
  Поляка.

Oracle и точные траектории остаются в диагностических CSV и графиках, но их
дополнительная статистика не перегружает итоговый JSON.

## Полный запуск

Из корня проекта:

```powershell
.\venv\Scripts\python.exe hb\pipeline.py
```

Параметры полного запуска по умолчанию:

| Параметр | Значение |
|---|---:|
| Диапазон `kappa` | `[1.1, 20000]` |
| Группы forward-датасета | 2400 |
| Кандидатов в группе | 96 |
| Итераций Heavy Ball | 300 |
| Начальных точек | 16 |
| Oracle-точек | 256 |
| Oracle-сетка | `64 x 64` |
| Пар `(L,l)` для финальных моделей | 10000 |
| ML-сетка обратного поиска | `64 x 64` |
| Точное локальное уточнение | два раза по `17 x 17` |

## Быстрая техническая проверка

Быстрый режим проверяет работоспособность, но не предназначен для получения
финальных метрик:

```powershell
.\venv\Scripts\python.exe hb\pipeline.py `
  --forward-groups 300 `
  --forward-candidates 48 `
  --forward-iterations 100 `
  --oracle-points 32 `
  --oracle-grid 24 `
  --oracle-refine 13 `
  --meta-pairs 500 `
  --meta-estimators 150 `
  --search-grid 24 `
  --predicted-refine 12 `
  --exact-top-k 12 `
  --exact-refine 9 `
  --batch-size 32
```

Быстрый запуск перезаписывает локальные данные и модели. После проверки для
анализа результатов нужно снова выполнить полный запуск.

## Использование готовых моделей

Пример для `L=1000`, `l=10`:

```powershell
.\venv\Scripts\python.exe hb\predict.py 1000 10
```

Скрипт выводит:

- входные `L`, `l` и `kappa`;
- finite-horizon прогнозы `alpha` и `beta`;
- внутренний параметр `q` и признак устойчивости;
- параметры Поляка для сравнения.
